# Drift API — 2026/04/13

## 1. Project

AI 白噪音生成 app 的后端服务。接收用户自然语言 prompt，由一个 agent 循环解析并拆分为多段 sound effect 生成指令，并发调用 ElevenLabs text-to-sound-effect API，返回原始音频段。

**混音留给前端**。后端只负责生成原始音频，前端用做本地即时混音（EQ、声场、音量、循环等用户可调参数）。

## 2. Scope (current phase)

跑通最小闭环：**Agent 解析 → 并发生成 sound effects → 返回原始音频**。

显式不做（全部经过讨论后决定延后）：

- ❌ 数据库 / ORM
- ❌ 对象存储（R2/S3）
- ❌ 任务队列（BullMQ / Redis）
- ❌ 鉴权 / 用户系统
- ❌ Stripe / 计费
- ❌ 混音 / ffmpeg / `plan` 字段
- ❌ SSE / WebSocket / 流式响应
- ❌ Rate limiting / CORS 细配置
- ❌ 测试套件（单元 / 集成）
- ❌ Dockerfile

## 3. Stack

| 层 | 选择 |
|---|---|
| Runtime + 包管理 | **Bun** |
| 框架 | **NestJS + Fastify adapter** |
| 架构风格 | **标准模块化**（**不**用 CQRS / DDD） |
| Agent SDK | **Vercel AI SDK**（`ai` + `@ai-sdk/openai`） |
| LLM | **OpenAI `gpt-5.4-mini`** |
| 音频 | **ElevenLabs text-to-sound-effect** |
| 校验 | **Zod**（env + tool params） |
| 日志 | **pino** via `nestjs-pino` |
| 并发控制 | **p-limit** |
| Node 基线 | Node 22 LTS 兼容 |

## 4. API

### `GET /health`
```json
{ "status": "ok" }
```

### `POST /generate`

**同步 HTTP**。请求连接 hold 到 agent 循环完成并所有 ElevenLabs 请求返回。

**Request**
```json
{ "prompt": "string" }
```

**Response 200**
```json
{
  "jobId": "uuid",
  "effects": [
    {
      "id": "rain_heavy",
      "prompt": "heavy rain on rooftop",
      "durationSec": 10,
      "audioBase64": "...",
      "mimeType": "audio/mpeg"
    }
  ]
}
```

**Error 5xx**
```json
{ "error": { "code": "...", "message": "..." } }
```
通过 Nest global exception filter 统一返回。

## 5. Agent Design

### 循环
使用 Vercel AI SDK 自带的自动 tool execution：

```ts
const result = await generateText({
  model: openai(env.OPENAI_MODEL),
  system: SYSTEM_PROMPT,
  prompt: userPrompt,
  tools: { generate_sound_effects },
  maxSteps: 5,
});
```

SDK 内部循环直到 `finishReason !== 'tool-calls'` 或达到 `maxSteps`。

### 唯一工具：`generate_sound_effects`

**Parameters**（Zod，字段对齐官方 `text_to_sound_effects.convert`）
```ts
z.object({
  effects: z.array(z.object({
    id: z.string(),                                      // agent 自己命名
    prompt: z.string(),                                  // text，传给 ElevenLabs 的英文描述
    durationSec: z.number().min(0.5).max(30),            // duration_seconds，官方上限 30s
    promptInfluence: z.number().min(0).max(1).optional(),// prompt_influence，默认 0.3
    loop: z.boolean().optional(),                        // 是否生成无缝循环（v2 模型支持）
  })),
})
```

**Execute** 流程：
1. `p-limit(3)` 并发调 ElevenLabs
2. 成功的 buffer 写入**请求级闭包 Map**（`Map<effectId, { buffer, meta }>`）
3. 返回给 LLM 的 `toolResult` **只含元信息**：`{ results: [{ id, status, durationSec, error? }] }`
4. **绝不**把 base64 或 buffer 回传给 LLM（token 爆炸）

### System prompt（初版）
```
You are a white-noise design agent.
Given a user's description, break it into concrete sound effects.
Each effect needs an accurate English prompt and a duration between 0.5 and 30 seconds.
Prefer specific, evocative prompts (e.g. "Heavy rain on a tin roof with distant thunder" over "Rain").
For ambient/background layers, set loop=true so the segment loops seamlessly.
Use promptInfluence around 0.3 by default; raise toward 0.6–0.8 when the prompt must be followed strictly.
Call generate_sound_effects once with all effects in parallel.
After reviewing the results, if all succeeded, stop. If any failed, retry only those.
```

后续根据实测效果迭代。

### Service 层装配
`audio.service.ts` 创建请求级 buffer Map，通过闭包注入到 tool 的 execute。循环结束后读 Map → base64 → 组装 response。Map 不泄漏到模块外。

## 6. ElevenLabs Client

- **SDK**：官方 `@elevenlabs/elevenlabs-js`，调用 `client.textToSoundEffects.convert(...)`。不手写 `fetch` 打 REST。
- **API key**：`new ElevenLabsClient({ apiKey: env.ELEVENLABS_API_KEY })`，模块启动时单例构造，由 Nest provider 注入。
- **模型**：`model_id: 'eleven_text_to_sound_v2'`（默认值；loop 仅 v2 支持，显式写出避免未来默认值漂移）。
- **请求参数映射**（工具参数 → SDK 字段）：
  - `prompt` → `text`
  - `durationSec` → `duration_seconds`（0.5–30；`null` 时由 API 自动判断，当前阶段始终显式传）
  - `promptInfluence` → `prompt_influence`（0–1，默认 0.3）
  - `loop` → `loop`
- **输出格式**：`output_format: 'mp3_44100_128'`（默认 MP3，前端混音够用；后续如要 PCM/Opus 再换）。
- **响应处理**：SDK 返回 `Readable`，在 client 内消费为 `Buffer`（`for await` chunk 累积），`mimeType` 固定 `audio/mpeg`，与 `output_format` 对齐。
- **超时**：单请求 60s（传 `AbortSignal.timeout(60_000)` 给 SDK 的 `requestOptions`）。
- **重试**：3 次指数退避（1s → 2s → 4s），仅对 5xx / 429 / 网络错误重试，4xx（含 401/422）直接失败。
- **并发**：`p-limit(3)`，在 `elevenlabs.ts` 内部持有一个模块级 limiter。
- **失败策略**：单段失败在 tool 返回里标记 `status: 'failed'` + `error`，由 agent 决定是否重试（system prompt 已指示只重试失败项）。

## 12. Decisions Log

讨论中做出并固定的决定：

- **同步 HTTP**，不上 job queue（scope 最小，后面真需要再切）
- **Agent 只用一个工具**：`generate_sound_effects`，不要 `finalize` / `plan`（混音由前端做）
- **Tool 结果对 LLM 只暴露元信息**，buffer 走请求级闭包 Map
- **Vercel AI SDK 自动 tool execution** via `maxSteps`，不手写循环（YAGNI，未来真要定制再展开）
- **Fastify adapter** 而不是 Express（性能、pino、TS 类型一致性）
- **标准 Nest 模块化**，不上 CQRS / DDD（过度工程）
- **Bun** 作为 runtime + 包管理器（TS 原生、启动快、生态已兼容）
- **base64 JSON 返回**而非 audio 二进制（多段无法单 response 返回二进制；前端需要分段处理）
- **所有基础设施（DB / 存储 / 队列 / 鉴权 / 混音）全部延后**，YAGNI
